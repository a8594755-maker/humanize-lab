Humanize Lab：原理、程式碼審查與本機原型

研究日期：2026-10-13（America/New_York）｜範圍：英文文章｜不訓練、不 fine-tune

結論：可以用既有 LLM API 搭配本機偵測、品質檢查與回溯，建立 humanize 原型。偵測分數下降是可測量的結果，但不等於文章真的由人類撰寫，也不保證對未測過的偵測器有效。

偵測器到底在看什麼？

方法原理整合判斷
Binoculars比較實際文字的平均負對數機率，與兩個模型分布的交叉熵之比；原版分數越低越像 AI。可提供模型機率訊號；不可把 clarity 當成另一個獨立方法重複投票。
Fast-DetectGPT把實際 token 的 log probability 與參考分布的期望值比較，再用變異數標準化；官方有不需抽樣的解析式。可作第二類統計訊號。範例百分比使用固定常態分布與均衡先驗，不能直接移用。
Ghostbuster組合弱語言模型、n-gram 與特徵搜尋，交給監督式分類器。適合研究特徵組合；原始 classify.py 依賴舊式 ada/davinci API，直接搬用有整合成本。
GLTR逐 token 看實際詞在語言模型預測中的排名、機率與分布。適合視覺化解釋，不是現成且經校準的文章來源百分比。
NTS比較不同溫度下的 token 機率變化。核心程式使用 Falcon-7B。可新增特徵；研究環境 A40 48 GB 不代表算法硬性需要同一硬體。
Lastde分析 token 機率序列的局部變化及全局統計。研究候選；不能假設和其他統計方法相互獨立。
DesklibDeBERTa-v3-large，加 attention-mask mean pooling 與單一 sigmoid 分類頭。第一版最後驗證模型。HF 是 MIT 標記；GitHub 主要提供 README 中推論類別。
Fakespot / ApolloDFT公開 RoBERTa 英文分類權重；完整 Apollo 結合監督與統計方法。第一版引導模型。公開分類器不等同完整商業 Apollo ensemble。
MAGE跨領域資料與 Longformer 分類器；官方 label 0 是 AI，1 是 human。可換作額外測試；整合時不可把標籤方向弄反。
SeqXGPT把多個 LLM 的 token 機率對齊，利用卷積／注意力做句子級分類。若研究人機混寫，這比把整篇分數硬套每一句更有針對性。
L2D比較文字與 LLM 重寫結果，學習可分辨來源的距離。可作重寫後偵測的研究候選；需額外生成成本。
RAID / MGTEval資料集、偵測器接口、校準與評估框架。用於實驗；框架不是一個新的獨立偵測器。

補查 Vanguard（ModernBERT）作為新候選：保存了模型卡與 config，但未下載其權重或測試效果。模型卡中的跨模型比較描述把 Desklib 寫成雙輸出 softmax，與 Desklib 官方單 logit sigmoid 範例不一致，因此不能只憑該比較宣稱優於 Desklib。Vanguard 模型卡。

從偵測到改寫：三條研究路線

普通受控改寫：DIPPER 控制詞彙變化、內容重排與上下文，是重要基線；它採用 11B 模型，原始範例直接載入 CUDA，對 12 GB 顯示記憶體並非理想起點。ai-detection-paraphrases/dipper_paraphrases/paraphrase_minimal.py。

不訓練、用偵測器引導：Adversarial Paraphrasing 官方實作在生成每個 token 時，評估候選延伸文字的偵測分數，再挑選下一步；這與「先生成幾個完整改寫，再排序」不同。前者需要本機生成模型的 token 分布、推論成本較高；後者可接一般 LLM API，適合本次原型。Adversarial-Paraphrasing/utils.py。

對抗訓練：RADAR 用改寫器與偵測器互相訓練；AuthorMist 探索把偵測器當強化學習回饋。這些適合解釋研究脈絡，但本次依照你的要求不做 fine-tune。RADAR/README.md；AuthorMist。

原始碼審查的重要發現

clarity 的研究數字不能直接搬到你的文章

作者的快速校準資料只有 10 篇 Claude 文字和 40 段 Python docstring；公布的約 40% detection @ 5% FPR 並非代表性英文論文測試。句子級閾值也沿用文件級閾值。clarity/docs/CALIBRATION.md

clarity 的 fast 模式不是官方 Fast-DetectGPT

其程式自行說明是近似量；而官方 get_sampling_discrepancy_analytic 已能解析計算，不需要 clarity 文件所暗示的多次全文生成。應採用官方核心或自行數值對照。clarity/src/clarity/fast_detect.py；fast-detect-gpt/scripts/fast_detect_gpt.py

現成 humanizer 的 Binoculars 分母不同

paniccow/humanizer 的 _bino_score 用實際 token 的另一個模型 NLL 作分母，沒有計算兩模型完整分布的交叉熵；也把 0.9015 說成低 FPR 閾值，而原版低 FPR 常數約 0.85364。它還用任意尺度 sigmoid 將分數變成 p_ai。本次沒有採用這段程式。humanizer/humanizer/detectors/binoculars.py；Binoculars/binoculars/detector.py

語意失敗時仍可能輸出

該 humanizer 的 fallback_to_best 預設 True：所有候選未通過相似度檢查，仍可能選分數最低者。本次改為保留上一個合格版本；若從未改善則保留原文。humanizer/humanizer/humanizers/adversarial.py

樣式分數改善不等於偵測器驗證

paniccow/humanizer 的 README 明確表示完整 LLM pipeline 尚未端到端測量，部分 headline 是規則型 pattern score。程式存在、單元測試通過、規則分數下降，均不足以證明跨偵測器成功。humanizer/README.md

本機原型實際流程

  1. 保留原文；Fakespot 對全文分 token 視窗計算基準分數，不只分析開頭。
  2. API 產生完整改寫，每輪 1–4 個候選，最多 3 輪。提示要求保留論點、限制條件、數字、引用與專名。
  3. 先檢查數字、引文、引用／網址、指定保留文字及篇幅。再用 MiniLM 雙向句子配對與 NLI 檢查可能遺漏和矛盾。
  4. 只有通過品質檢查，且 Fakespot 分數比目前最佳版本降低超過 0.005 才接受；否則回溯。一整輪沒有改善就提早停止。
  5. 最後才用 Desklib 分別檢查原文與選定版本，不用它挑候選。若它沒有同步改善，介面會直接說明。
  6. 顯示原文、輸出、兩組分數、文字差異、候選失敗原因，支援 JSON 匯出。可中止後續請求。

品質門檻（例如篇幅 80%–125%、相似度 0.68、矛盾分數 0.65）是明確的原型設定，未在目標課程資料上校準。相似度不是事實正確率，NLI 也會誤判；人工核對仍是評估的一部分。規則只提供編輯提示及品質約束，沒有偽裝成「AI 機率」。

學校專案應如何實驗

比較四組：原文、一次普通 LLM 改寫、best-of-N、加入品質閘門與回溯。固定相同的 LLM、候選數與 token 預算，避免把更多 API 費用誤認為方法進步。每組至少先用多主題的小型 pilot，確認流程後再擴大；單篇示範只能驗證可運作，不能推論整體有效率。

資料分成調整集與封存測試集；以來源、題目、作者／生成模型分組，原文及其所有改寫不得跨組。Fakespot 是引導器，Desklib 是本原型最後檢查器；若人看過 Desklib 結果又繼續調參，它也變成開發資料，最終研究需另留從未參與選擇的模型或資料。

報告指標：每個偵測器改寫前／後的分數和 TPR@固定 FPR、原本被偵測出的文章中有多少在改寫後低於同一閾值、原本未被偵測的比例、品質通過率、事實／數字／引用保持率、盲評自然度、API 次數／成本／延遲。將「偵測成功率降低」和「內容品質維持」分開報告。不要只報平均分數或挑選成功例子。

RAID、MAGE 可提供起點，但 Desklib 模型卡與 Fakespot 技術文件涉及 RAID；因此不能把整個 RAID 自動當作完全未見過的獨立測試。需要去重、查訓練來源，並補充新題目、新生成模型及經確認來源的人類英文文本。raid/README.md；apollodft/apollo-text.md。

為何不顯示「人類 90%、AI 10%」

偵測分數、二分類信心、真實來源後驗機率、AI 參與文字比例，是不同概念。只有先明確定義「AI 生成」與「人類撰寫」，並在代表性獨立資料上校準，才有條件顯示二分類機率；人機混寫與 AI 潤稿不能被强迫解釋為兩種互斥來源。

若未來做 detector ensemble，使用不同方法的原始分數／logits 作特徵，在分組 out-of-fold 資料上學習融合權重，再以獨立校準集做 Platt／isotonic calibration，最後用封存測試集看 Brier、可靠度圖與 FPR。不能把相關方法的百分比直接平均成可信的真實機率。

本機資源與範圍

本次實際讀到 RTX 5070 Ti Laptop GPU，約 12 GB VRAM、31.1 GiB 系統 RAM。第一版僅在本機執行分類／語意模型，四個 safetensors 權重合計約 2.9 GB；不載入大型改寫 LLM，改寫交給使用者 API。雙 7B 的 16-bit 權重粗估約 28 GB，尚未計算中間張量，因此原版 Binoculars 不適合直接全部放在這張卡上。

下載與權重不等於可任意重新授權。保留原始 LICENSE；GitHub 無根目錄 LICENSE 的研究專案只列為公開原始碼參考，不能直接視為有完整再散布授權。本次原型自行實作流程，沒有複製這些無授權聲明的程式。模型授權與資料授權應分別記錄。
